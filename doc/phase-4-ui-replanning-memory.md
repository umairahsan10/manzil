## Goal

Match the section-12 user-experience sketch end-to-end. The hero widget
(scorecard heatmap), the dissent block, the why-not summaries, the map
view, and the day-by-day plan all render properly. Replanning under a
disruption produces a side-by-side comparison. The post-trip feedback loop
demonstrably changes the next recommendation.

By the end of this phase, **the demo flow exists in full**.

## Why this phase

Phase 3 finished the brain. This phase finishes the face. A demo where the
brain is right but the face is rough still leaves the audience cold. This
phase is also where the most visible differentiator (the scorecard heatmap)
gets built — that is the single widget most likely to come up in defense
questions.

Replanning is the thing that turns "smart suggestion" into "decision
support" — a one-shot tool can pick a winner; only an interactive one can
adapt to a disruption.

The memory loop closes the personalization claim from the readme.

## Inputs / preconditions

- Phase 3 verified — full debate runs, all 5 agents real, dissent and

  `Disruption` schema in place**

## Deliverables

### UI components (Person 3)

| File | Responsibility |
|---|---|
| `ui/components/map_view.py` | Folium map. Show the 3 candidate routes as 3 colored polylines on first render. Once the winner is picked, fade the runner-ups and bold the winner. Stops are circle markers with hover-popups (name, altitude, day index). |
| `ui/components/scorecard.py` | **The hero widget.** A 5×3 heatmap (5 agents × 3 candidates) with cell coloring by score. Veto cells are crossed out and tinted red. Click a cell → shows that agent's reasons + concerns for that candidate in a side panel. |
| `ui/components/debate_trace.py` | A streaming animation. Each agent's argument fades in as it completes. Cosmetic, but it makes the debate feel real and is great in the demo. Implement with `st.empty()` + `time.sleep(0.4)` between steps. |
| `ui/components/day_by_day.py` | Renders the `DayByDayPlan` for the winning route. Per day: stop list, drive segment, weather note, road note, safety flag, one local-experience tip. Collapsible per day. |
| `ui/components/dissent.py` | Pulls `DebateResult.dissenting_opinion` (the LLM-synthesized natural-language dissent). Renders inside an alert-style box only when non-null. |
| `ui/components/why_not.py` | Renders `DebateResult.why_not` for the two runner-ups as one-line plain-language explanations: *"Route A scored higher on cultural value but the Weather Agent flagged a 35% flight-cancellation risk."* |

## Acceptance criteria

The full section-8 user flow runs cleanly in one sitting:

1. User opens the app, fills the form, submits.
2. 3 candidate cards appear on a map with one-line summaries within ~3s.
3. The debate-trace animates; agent arguments fade in. ~10–15s with cold
   cache, sub-second with warm cache.
4. Winner section renders: full day-by-day plan + scorecard heatmap +
   dissenting opinion (when applicable) + why-not summaries for both
   runner-ups + map highlighting the winning route.
5. User clicks "Replan with disruption", picks `road_closed` on day 3.
   Side-by-side view shows the original winner and the replanned winner;
   the Road Agent's blocker on the original is visible in the new
   scorecard.
6. User clicks "Submit feedback", rates 2/5, tag `too-rushed`. A similar
   query 30 seconds later returns a slower-paced recommendation. The new
   winner traces back to the just-submitted case (logged for verification).

Plus:

- `pytest tests/test_feedback_loop.py` passes.
- The scorecard heatmap is screenshot-quality (deserves to be the cover
  image of the report).
- No race conditions on `case_base.json` writes (atomic write via
  tmp-file + rename, like our cache layer).

## Risks & Plan B

| Risk | Likelihood | Plan B |
|---|---|---|
| Folium map performance is rough on 3 overlapping routes | Low | Use Pydeck instead — slightly more work, much faster on dense routes. |
| Streamlit re-run loop kills the debate-trace animation | Medium | Use `st.session_state` to remember which agents have already animated; only animate on first run. Or skip the animation entirely — it's cosmetic. |
| Replanning re-run hits LLM rate limit (16 calls × 2 = 32 in <60s) | Medium | The cache absorbs most of this. Pre-warm common disruption variants in `seed_caches.py` (Phase 5). |
| Hot-reload of case base is racy under simultaneous writes | Low | Atomic tmp-file rename (already the pattern we use in `cache.py`). |
| Feedback loop "visibly different" claim doesn't reproduce reliably | Medium | Tighten the test in `test_feedback_loop.py` — boost the rating signal weight in CBR if necessary. The point is the loop *can* show personalization, not that it *always* will on weak signals. |
